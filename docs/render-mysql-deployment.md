# Render + MySQL Deployment Runbook

This project uses Django + MySQL because that is the requested portfolio stack.

## Important architecture choice

Render's Django quick-start examples commonly use PostgreSQL, while Render also documents MySQL as a private service backed by a persistent disk. For this project, keep the web service and MySQL private service in the same Render workspace and connect Django through `DATABASE_URL`.

## Step 1 — GitHub

Push the `fitbite` folder to a GitHub repository.

```bash
git init
git add .
git commit -m "Build FitBite digital marketing portfolio"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/fitbite.git
git push -u origin main
```

## Step 2 — MySQL service

In Render:
1. Create a MySQL 8 private service using Render's MySQL deployment option.
2. Wait for the MySQL service to become available.
3. Record the internal host, port, database name, username and password.

Do not put the password into GitHub.

## Step 3 — Django database URL

Build the value conceptually as:

```text
mysql://USERNAME:PASSWORD@INTERNAL_MYSQL_HOST:3306/DATABASE_NAME
```

If your password contains reserved URL characters, URL-encode them before using the value in a connection string.

## Step 4 — Web service

Create a Python Web Service from the GitHub repo.

- Build command: `./build.sh`
- Start command: `python -m gunicorn config.wsgi:application`

Environment variables:

```text
DEBUG=False
SECRET_KEY=<generated by Render>
ALLOWED_HOSTS=<your-service>.onrender.com
SITE_URL=https://<your-service>.onrender.com
DATABASE_URL=<your MySQL connection string>
EMAIL_HOST=<SMTP host if configured>
EMAIL_PORT=587
EMAIL_HOST_USER=<SMTP username>
EMAIL_HOST_PASSWORD=<SMTP password>
EMAIL_USE_TLS=True
DEFAULT_FROM_EMAIL=<verified sender>
GA4_MEASUREMENT_ID=<optional>
GSC_VERIFICATION=<optional>
```

## Step 5 — First admin user

After deployment, use the Render Shell:

```bash
python manage.py createsuperuser
```

Then open:

```text
https://<your-service>.onrender.com/admin/
```

## Step 6 — Seed demo data

If the database is empty, run in the Render Shell:

```bash
python manage.py seed_demo
```

This inserts five blog posts, five email campaigns and seven days of traffic-source metrics. The campaign and analytics records are marked simulated.

## Step 7 — Verify

- `/`
- `/campaign/`
- `/blog/`
- `/dashboard/`
- `/campaign-report/`
- `/admin/`

## Step 8 — Optional real email

Only after you have a real verified sender and permission-based list should you configure SMTP/Brevo/Mailchimp. Keep credentials in environment variables.

## What you can say in an interview

“I deployed the Django application on Render and connected it to MySQL through an environment-based database URL. I kept secrets outside the repository and used a seed command for clearly simulated portfolio data.”
